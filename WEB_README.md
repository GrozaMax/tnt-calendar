# Веб-интерфейс CrossFit Hub

Веб-интерфейс для управления тренировками и пользователями CrossFit Hub.

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка окружения

Добавьте в файл `.env`:

```env
# Web Interface
WEB_HOST=0.0.0.0
WEB_PORT=8000
WEB_DEBUG=true
WEB_SECRET_KEY=your-secret-key-here
```

### 3. Запуск веб-сервера

```bash
python run_web.py
```

Или напрямую через uvicorn:

```bash
uvicorn web.main:app --host 0.0.0.0 --port 8000 --reload
```

### 4. Вход в систему

1. Откройте http://localhost:8000
2. Введите ваш **Telegram ID** (узнать можно у бота @userinfobot)
3. Введите секретный код: `secret123`
4. Нажмите "Войти"

## 📚 API Документация

После запуска сервера доступна автоматическая документация:

- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

## 🔐 Авторизация

### Получение токена

Токен можно получить двумя способами:

#### 1. Через веб-интерфейс (рекомендуется)

1. Откройте http://localhost:8000
2. Введите Telegram ID и секретный код
3. Токен сохранится автоматически в браузере

#### 2. Через API

```bash
curl -X POST "http://localhost:8000/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{
    "telegram_id": 123456789,
    "secret_code": "secret123"
  }'
```

### Использование токена в API

Все запросы к API требуют авторизации. Добавьте токен в заголовок:

```bash
curl -X GET "http://localhost:8000/api/workouts/" \
  -H "Authorization: Bearer YOUR_TOKEN_HERE"
```

## 🔧 API Endpoints

### Авторизация

- `POST /api/auth/login` - Вход в систему
- `GET /api/auth/me` - Информация о текущем пользователе

### Тренировки

- `GET /api/workouts/` - Получить список тренировок
- `GET /api/workouts/{id}` - Получить тренировку
- `POST /api/workouts/` - Создать тренировку
- `PUT /api/workouts/{id}` - Обновить тренировку
- `DELETE /api/workouts/{id}` - Удалить тренировку
- `GET /api/workouts/{id}/participants` - Список участников
- `POST /api/workouts/bulk-create` - Массовое создание расписания

### Пользователи (только админы)

- `GET /api/users/` - Получить список пользователей
- `GET /api/users/{id}` - Получить пользователя
- `PATCH /api/users/{id}/role` - Изменить роль
- `GET /api/users/stats/summary` - Статистика

## ⚙️ Настройка

### Изменение секретного кода

По умолчанию секретный код: `secret123`

Чтобы изменить, отредактируйте файл `web/api/auth.py`:

```python
if request.secret_code != "your_new_secret":
    raise HTTPException(...)
```

### Production настройки

Для production окружения:

1. Установите `WEB_DEBUG=false` в `.env`
2. Измените `WEB_SECRET_KEY` на случайную строку
3. Используйте HTTPS
4. Настройте nginx как reverse proxy
5. Используйте PostgreSQL вместо SQLite
6. Настройте CORS если нужно

### Пример nginx конфигурации

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 🐛 Решение проблем

### Ошибка: Module 'fastapi' not found

```bash
pip install fastapi uvicorn
```

### Ошибка: 401 Unauthorized

Проверьте:
1. Токен корректен и не истёк
2. Пользователь существует в БД
3. Роль пользователя - Trainer или Admin (не Athlete)

### Ошибка: 403 Forbidden

Проверьте права доступа:
- Тренеры могут редактировать только свои тренировки
- Управление пользователями доступно только админам

## 📊 Массовое создание расписания

Веб-интерфейс использует шаблон из файла `create_weekly_schedule.py`.

Чтобы создать расписание на несколько недель:

1. Перейдите на вкладку "🗓️ Расписание"
2. Выберите количество недель (1-12)
3. Нажмите "Создать расписание"

Система автоматически:
- Пропустит прошедшие даты
- Не создаст дубликаты существующих тренировок
- Покажет статистику созданных/пропущенных тренировок

## 🔄 Интеграция с Telegram ботом

Веб-интерфейс и Telegram бот используют одну БД:
- Все изменения в веб-интерфейсе сразу видны в боте
- Атлеты могут записываться через бота на тренировки, созданные в вебе
- Тренеры могут просматривать участников в обоих интерфейсах
